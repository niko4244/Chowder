## Phase 1 — fix the two boundedness bugs in `run_search`

File: `src/chowder/growth/candidate_search.py`. Both were reproduced against the real
module; both are in `run_search`, the function whose docstring promises "the cost is
bounded before it is spent."

### 1.1 The overrun stop does not stop the round (live)

`stopped_by` is set inside the per-candidate loop but only breaks *between* rounds
(`candidate_search.py:452` and `:456`). Remaining candidates in the current round
still train after the campaign ceiling has tripped. The single-pass path in
`run_campaign` breaks immediately, so a declared search silently buys up to
`(round_size - 1)` extra attempts past the ceiling.

**Reproduced:** stop fired on attempt 1; `['r0','r1']` both ran.

**Change:** after the `stopped_by = should_stop(...)` assignment, break out of the
inner `for recipe_id in candidates:` loop when `stopped_by` is set. Keep the existing
between-rounds break. The partial round's attempts must still be appended to
`round_attempts` and still be charged — a stopped round keeps its spend in the record.

### 1.2 The plan/recipes guard is one-directional (latent)

`candidate_search.py:411-412` checks that the plan's ids are a subset of the recipes,
but line 420 seeds `survivors = tuple(by_id)` — *all* recipes passed in, not
`plan.rounds[0].recipe_ids`. Recipes the plan never projected get trained in round 0
with no refusal.

**Reproduced:** plan projected over `('r0','r1')`; run with 4 recipes trained
`['r0','r1','r2','r3']` in round 0 — double the admitted budget, silently.

This is contained *today* only because `run_campaign` happens to pass the same
`recipes` to both `search_plan_for` and `run_search`. That is a property of the
caller, not an invariant of the module.

**Change:** seed `survivors` from `plan.rounds[0].recipe_ids` rather than `by_id`.
(Alternative: make the guard symmetric and also refuse recipes the plan did not
project. Prefer seeding from the plan — it makes the plan the single authority over
who runs.)

### 1.3 Regression tests — required, one per bug

Add to `tests/test_growth_candidate_search.py`, matching the existing file's fixture style.

* `test_stop_ends_the_round_it_fires_in` — a `should_stop` returning a reason on the
  first attempt; assert exactly **one** `run_attempt` call, `stopped_by` set, and the
  partial round present in `round_attempts` with its attempt recorded.
* `test_run_refuses_recipes_the_plan_did_not_project` — plan over 2 recipes, run with
  4; assert only the 2 planned ids are trained (or `CandidateSearchRefusal` is raised,
  matching whichever fix was chosen).
