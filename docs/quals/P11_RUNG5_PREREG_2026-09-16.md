# P11 rung 5 — router-numerics fix: non-degenerate gate initialization + a bounded logit range, with a saturation instrument

**Frozen 2026-09-16, before any implementation and before any run.** Branch
`fix/rung5-router-numerics`, cut from `origin/main` = `1a4d35f`. This document
and its judge (`judge_rung5_2026-09-16.py`) are committed and pushed as one
preregistration bundle; the implementation they require lands afterwards on
the same branch, and the four arms run against the frozen pins below.

## 0. Why this rung exists, and what it replaces

The layer-31 diagnosis (2026-09-16,
`Chowder-Protected/runs/2026-09-16-layer31-gradient-diagnosis/DIAGNOSIS_2026-09-16.md`)
established by measurement that the HotCore router's failure is a **numerics
latch**, not an under-trained optimizer:

- The artifact ships `model.layers.{0..31}.mlp.gate.weight` exactly zero. With
  gain 1, Adam's first step is ±lr = **±0.05** per element from zero — the
  fastest possible route to a saturated softmax.
- The gate then grows until the top-2 logit gap crosses the softmax's exact
  underflow point, and the softmax becomes **exactly** one-hot. L31 trained:
  logit absmax 456–600, gap 456–600, **128/128 rows exactly one-hot**, with
  `1920/1920` non-selected probabilities exactly `0.0` — in bf16 **and** fp32.
- With `p` exactly one-hot, `dL/dlogits ≡ 0` identically. L31's weight-gradient
  absmax is `0.000e+00` and its gate-output gradient norm is `0.0`, on **40 of
  48 steps**.
- Adam cannot recover it: a zero first moment gives no update, and the ε floor
  kills subnormal gradients. Weight decay cannot rescue it either (at lr 0.05,
  wd 0.01 the per-step shrink is 0.075 ULP and rounds back to the same value —
  verified on the real trained values).

Scaling the *same trained gate* on the *same batch* walks across the threshold
and shows that "gradient nonzero" is not liveness:

| gate × factor | top-2 gap | rows exactly one-hot | `\|wgrad\|`max |
|---|---|---|---|
| 0.0 | 0 | 0/128 | 9.375e-02 — healthy |
| 0.25 | 132 | 30/128 | 1.214e-16 — nominal only |
| 0.5 | 264 | 126/128 | 5.639e-31 — nominal only |
| 1.0 (as trained) | 528 | 128/128 | 0.000e+00 — dead |

The latch is set by the **deep layer's input activation scale** (L31 spreads
≈1800 logits per unit of gate weight, L0 ≈82), not by runaway gates: latched
layers carry *smaller* gates (0.293) than healthy ones (0.79–1.30).

This rung does two things the diagnosis ranked as independently testable, and
one thing it demanded as an instrument fix:

1. **Non-degenerate gate initialization** — zero-init is a property of artifact
   preparation, so every router run on this artifact starts at maximum
   symmetry with maximum first-step size.
2. **A bounded logit range** — so the top-2 gap cannot cross the underflow
   threshold by construction.
3. **A saturation instrument** that reports rows-exactly-one-hot and gradient
   *magnitude* instead of the binary grad-nonzero flag, because a nonzero
   gradient at 1e-31 is not liveness and the current contract cannot tell
   latched from learning (rung 4's contract read healthy on L31, which had a
   zero gradient on 40 of 48 steps).

This rung **supersedes neither rung 4 nor rung 4b/4c as a record** — their
negative results stand. It replaces the *contract* they were judged by.

### 0.1 What this rung does not claim

- **No routing-concentration claim.** The census metric is argmax-top-1 dead
  experts, a *concentration* measure. This rung's claim is *trainability*. The
  two are different phenomena (measured: L4 and L21 are equally collapsed at
  15/16 censused-dead experts yet have 48/48 nonzero gradients). `dead_experts_after`
  is gated only for **non-inferiority**.
- **No generation-sanity claim.** No `generation_probe` block is configured, so
  the evaluation leg runs no generation probe. The rung-4 generation probe
  (8 prompts × 32 new tokens × 2 arms, measured 182.13 s) cost 15.8× its frozen
  sub-budget and belongs to a capability rung; generation sanity is explicitly
  out of scope here, not silently dropped.
- **No promotion claim.** These are 48-step router-only runs over 6144
training tokens. Nothing here qualifies HotCore as a useful model.

## 3. The intervention (frozen)

### 3.1 New spec fields

Four fields, added to the router-healing project config, validated and included
in the spec digest like every other knob:

| Field | Type | Meaning |
|---|---|---|
| `gate_initialization` | `"artifact"` \| `"small_normal"` | `"artifact"` (default) uses the loaded gates unchanged — rung-4 behaviour. `"small_normal"` re-initializes every trainable gate before step 1. |
| `gate_init_std` | positive finite float, required with `"small_normal"`, forbidden otherwise | Standard deviation of the initialization. |
| `router_logit_scale` | positive finite float or `null` (default) | Divides the gate output before the softmax/top-k. |
| `router_logit_soft_cap` | positive finite float or `null` (default) | Bounds the (scaled) routing input. |

Validation is a refusal, not a coercion: a non-positive, non-finite, or
boolean value is refused; `gate_init_std` without `"small_normal"`, or
`"small_normal"` without `gate_init_std`, is refused.

### 3.2 Frozen forward composition

For gate output `z` (the `mlp.gate` Linear, no bias):

```
u = z                                  if router_logit_scale is None else z / router_logit_scale
v = u                                  if router_logit_soft_cap is None else C * tanh(u / C)
p = softmax(v);  top-2 selection over v
```

`v` — not `z` and not `u` — is the routing input, and therefore the quantity
the census, the one-hot test, and the gap test all read.

The **null path must be a bit-identical no-op**: with `router_logit_scale = None`
and `router_logit_soft_cap = None`, the composition must return `z` unchanged,
so arm A's routing math is exactly rung 4's. This is required by a unit test
(§4.5), not asserted here.

### 3.3 Frozen initialization

When `gate_initialization = "small_normal"`, before `optimizer.step()` 1 and
after the frozen-weight digest is taken, every trainable gate `W`
(shape 16×4096) is drawn as `W ~ Normal(0, gate_init_std²)` from a
`torch.Generator` seeded with the run seed, cast to the parameter's dtype.

Recorded in the worker result so the initialization is reproducible and
auditable: `gate_init_std`, `gate_init_seed`, `initialized_gate_digest`
(sha256 over the initialized gate tensors), and the per-gate preflight readings
of §4.4. The frozen-weight digest (`frozen.changed == {}`, 523 frozen
parameters) is taken **after** the initialization, so re-initializing a
trainable gate can never appear as frozen-weight drift.

### 3.4 Why a rescale **and** a cap, rather than a cap alone

The router's parameter gradient is

```
dL/dz_m = p_m [(g·w_m) − E_p(g·w)] · dv_m/du_m
```

Both factors die as the softmax concentrates: the bracket vanishes as `p_m → 1`
(measured: gap 0 → `|wgrad|` 9.375e-02; gap 132 → 1.214e-16; gap 264 →
5.639e-31), and `dv/du = sech²(u/C)` vanishes when the pre-cap input is far
outside the cap. A cap alone therefore trades an **exactly zero** gradient for a
**vanishing** one — the same functional failure the latch produces, and one
this rung's liveness test would still catch (`implied_update` below the bf16
half-ULP).

So the rescale carries the operating point and the cap makes the bound
structural:

- The rescale puts the operating logits in the measured live regime, so the
  bracket term stays within `e^-10` of unsaturated.
- The cap removes the possibility that a future gate growth walks the gap back
  over the underflow threshold.

### 3.5 Frozen values, and their derivation from measurement

| Knob | Value | Derivation |
|---|---|---|
| `router_logit_scale` | **128.0** | The latch requires the top-2 gap to exceed the softmax's exact-underflow point: bf16 `exp` underflows at gap ≳ **92.4** (`ln(1/9.18e-41)`), fp32 at ≳ **103.3**. The declared operating target is a post-scale gap ≤ **10**, so the bracket stays within `e^-10 = 4.5e-05` of unsaturated and Adam's update `lr·g/(g+ε)` stays within 0.1% of full size. The largest measured gap on the real artifact is **528** and the largest measured logit absmax **600** (2026-09-16), so `scale ≥ 600/10 = 60`. **128** is the next power of two above that, a 2.13× margin. |
| `router_logit_soft_cap` | **30.0** | `C·tanh(u/C)` bounds the gap by `2C = 60`, i.e. **0.65×** the bf16 underflow threshold of 92.4. The margin covers the logits' own bf16 quantization (ulp 0.125 at `\|v\| = 30`, 0.2% of the bound). In the declared operating regime (`\|u\| ≤ 5`) the compression is `sech²(5/30) = 0.973` — a 2.7% gradient attenuation, i.e. near-identity where it operates. |
| `gate_init_std` | **1.0e-3** | The gate is 16×4096 and the measured per-unit-weight logit gain is ≈82 (L0) to ≈1800 (L31), i.e. `‖x‖` in that range. `W ~ N(0, s²)` gives `\|z\| ~ s·‖x‖`, so `s = 1e-3` yields initial `\|z\|` ≈ **0.08** (L0) to **1.8** (L31), and `\|u\|` ≈ 6e-04 to 1.4e-02 — inside the operating regime, near-uniform routing with genuine per-row variation. **The value is not taken on faith**: §4.4 measures the outcome on the real first batch and arm D refuses before step 1 if the degeneracy was not actually broken. |

The network's own `router_aux_loss_coef`, `output_router_logits`, z-loss and
temperature remain **untouched and unset** — the HotCore config carries none,
and the diagnosis's finding 4 is that a balancing loss is prophylactic, not
curative, for a layer whose Jacobian is already exactly zero. This rung does
not add one.

## 4. The saturation instrument (frozen contract)

The instrument replaces the binary grad-nonzero flag as the evidence of
liveness. It is an *upgrade* of the existing record, not a replacement of it:
every existing `trainability` key remains, so rung 3b/3c/4 records stay
readable and the judge can cross-check old against new.

### 4.1 Per-gate fields (added to `trainability.components[name]`)

Per step, for each of the 32 gates, over the **training batch of that step**
(128 rows = `batch_size` 2 × `seq_len` 64):

| Field | Type | Meaning |
|---|---|---|
| `grad_absmax_by_step` | list[float] | `max(abs(parameter.grad))` after backward, before the optimizer step |
| `softmax_input_absmax_by_step` | list[float] | `max(abs(v))` — the routing input actually used |
| `top2_gap_max_by_step` | list[float] | max over rows of `v_(1) − v_(2)` |
| `rows_exactly_one_hot_by_step` | list[int] | rows whose softmax output has exactly one nonzero entry |
| `implied_update_by_step` | list[float] | `learning_rate · grad_absmax / (grad_absmax + adam_eps)` — AdamW's update magnitude for the measured gradient, using the worker's actual optimizer constants |
| `half_ulp_by_step` | list[float] | `0.5 · eps(dtype) · max(abs(W))` — half a ULP at the parameter's own scale |
| `gradient_moves_parameter_by_step` | list[bool] | `implied_update > half_ulp` |

Aggregates per gate: `rows_total_per_step` (int, 128),
`any_exactly_one_hot_steps`, `fully_one_hot_steps`,
`max_exactly_one_hot_fraction`, `max_top2_gap`, `min_softmax_input_absmax`,
`grad_absmax_min`, `min_implied_update`,
`steps_with_gradient_not_moving_parameter`.

Per run: `trainability.instrument = {"version": "saturation.v1",
"rows_per_step": int, "gates_observed": int, "declared_scale": float|null,
"declared_soft_cap": float|null, "declared_init": str,
"adam_eps": float, "learning_rate": float, "dtype": str}`.

`adam_eps` and `learning_rate` are recorded because the liveness derivation is
unbound without them: an unbound derivation is a number with no arithmetic
behind it. The workload's schedule is constant (`warmup_steps` 0, no schedule
configured), so the per-step effective learning rate equals the declared
`learning_rate`; a rung that introduced a schedule would have to record the
per-step series instead, and this prereg does not.

### 4.2 The liveness test, and why it replaces the flag

`update_steps` (the existing field) records that a parameter *changed* — and it
read 0..32 on L31 while the gradient was zero on steps 8..47, because a stale
Adam first moment keeps moving the parameter for ~30 steps after the gradient
dies. **"The parameter moved" is not liveness.** The instrument's test is
instead a derived comparison between two measured quantities and one dtype
constant:

```
implied_update = learning_rate * |grad|_max / (|grad|_max + adam_eps)
half_ulp       = 0.5 * eps(dtype) * max|W|
moves          = implied_update > half_ulp
```

All three inputs are measured or declared: `learning_rate` and `adam_eps` are
the worker's own optimizer constants, recorded in the instrument block, and
`eps(dtype)` is a dtype constant. A judge can therefore re-derive every liveness
flag from the stored gradient and parameter magnitudes, so a run cannot report
a healthy flag beside a dead gradient.

Calibration against the measured counterfactual: at gap 0 the healthiest
reading gives `implied_update ≈ 0.0500` against `half_ulp ≈ 5.7e-04` → **moves**
(true); at gap 132 it gives `implied_update ≈ 6.1e-10` against the same
`half_ulp` → **does not move** (≈9 orders below), which is exactly the
diagnosis's finding. The test separates the two regimes by six orders of
magnitude and needs no threshold invented from nothing.

### 4.3 Cost

**Zero added forward or backward passes.** Every field above is read from the
training step that already runs: `p`/`v` from a forward hook on the gate,
`grad` from `parameter.grad` after the existing `backward()`, and the parameter
scale from the existing parameter. The step-cost ceiling (3.5 s/step) is
unchanged; the wall envelope (§5) carries a declared 2% allowance for the
tensor reads a blocked `.item()`/`norm()` per step implies.

### 4.4 Preflight readings, and the refusal that is scoped to the fix

Before `optimizer.step()` 1, on the first training batch, per gate:

- `initial_gate_output_absmax` — raw `max|z|` (diagnostic only, never a threshold).
- `initial_softmax_input_absmax` — `max|v|`; the routing input.
- `initial_logit_rms` — `sqrt(mean(v²))`.
- `initial_rows_with_exactly_equal_top2` — rows whose top-1 and top-2 routing
  inputs are **exactly equal** (the tie that argmax resolves to index 0).

**Recorded location (pinned, so the judge is implementable):** these readings
are emitted as a top-level `gate_initialization` block in the train worker's
`worker-result.json`:

```
gate_initialization = {
  "version": "gate-init.v1",
  "mode": "artifact" | "small_normal",
  "init_std": float | null,
  "init_seed": int | null,
  "initialized_gate_digest": str | null,
  "rows_total": int,
  "refused": bool,
  "refusal_reason": str | null,
  "gates": { "<gate name>": {
      "initial_gate_output_absmax": float,
      "initial_softmax_input_absmax": float,
      "initial_logit_rms": float,
      "initial_rows_with_exactly_equal_top2": int } }
}
```

**Refusal (arm-scoped, before step 1):** when `gate_initialization == "small_normal"`,
the run refuses if any gate reports `initial_rows_with_exactly_equal_top2 > 0`
(the initialization did not break the degeneracy) or
`initial_softmax_input_absmax > 10.0` (the fix starts in a saturated regime).
This makes `gate_init_std = 1.0e-3` self-checking on the real artifact rather
than assumed.

When `gate_initialization == "artifact"` those readings are **recorded and not
refused**: the artifact's gates are exactly zero by construction, and
reproducing that degeneracy is the control's entire purpose. Arms A and C are
expected to show `initial_rows_with_exactly_equal_top2 == rows_total_per_step`
on all 32 gates.

### 4.5 Instrument-neutrality requirement

Two unit tests are required (failing first, before the implementation):

1. With both knobs `None`, the composed routing input equals the gate output
   bit-for-bit.
2. A synthetic training step through the instrumented loop produces the same
   gradients and the same parameter update as the same step through the
   uninstrumented path.

Neither test is a substitute for arm A; they bound the instrument's own
footprint.

### 5.1 Wall-charge reconciliation (mandatory since rung 3c)

Wall charges (registry `gpu_hours`) are goal accounting billed on wall time;
the preflight ceilings above govern the device basis. The bridge is the run
class's measured wall multiplier **M = wall GPU-h / device GPU-h**, taken from
rung 4's train leg, which is the same class (cuda, paired, 48 steps,
`bf16-offload-transient`, same artifact):

```
M = 0.05632575761112902 wall (registry training_runs.gpu_hours, = 202.77272740006447 s)
  / 0.04221518519444443 device (lifecycle.measured_gpu_hours)
  = 1.3343
```

Both numerator and denominator are read from rung 4's own registry row and
worker result, not from a summary.

The template's prediction form gives `0.0710 × 1.3343 = 0.09473199683881643`
per arm. The workload form agrees and is smaller: the measured same-class walls
are 202.77272740006447 s (rung-4 train) + 61.46920449996833 s (rung-3c eval),
i.e. 0.07340053663889799 GPU-h per arm; with the instrument's declared 2%
train-leg allowance that becomes 0.07452705179112058.

The two forms disagree by design: the template form uses the per-process device
*ceiling* (0.0710) as if it were a measurement, so it over-predicts by
construction, while the workload form uses the measured same-class walls.

**Envelope: declared 0.1200 per arm** — above both forms, at 1.27× the
template's conservative prediction, 1.61× the workload prediction, and 2.40×
the arm's two-leg device projection. **Campaign envelope: 0.4800 for four
arms.** The headroom is deliberate: an envelope set a hair above a
conservative estimate would turn ordinary wall variance into a NOT CERTIFIED
verdict for an accounting reason, which is noise rather than evidence. The
envelope is a recorded goal, not a refusal threshold — exceedance is surfaced
by the judge and recorded by a human; refusal stays on the device basis.

Ledger note (fixed 2026-09-15, applies here): a paired baseline row no longer
re-charges the shared resident wall — it records `gpu_hours` 0.0 with the
shared charge disclosed in `compute.shared_wall_gpu_hours` and

  `run_ceiling.measured == true` and `would_exceed_ceiling == false`, every

- **T5 horizon** — per arm: `steps_completed == 48`, `global_step == 48`,

### 6.1 New saturation thresholds

- **N1 (no fully-one-hot step)** — arm **D**: for every one of the 32 gates,
  `fully_one_hot_steps == []`. Grounded in §3.5: the cap bounds the gap below
  60 < 92.4, so no row can be exactly one-hot, and this threshold is the
  structural claim's empirical confirmation.
- **N2 (every step's gradient can move its parameter)** — arm **D**: for every
  gate, `steps_with_gradient_not_moving_parameter == []`, i.e.
  `implied_update > half_ulp` on all 48 steps. This is the liveness threshold
  the binary contract could not express.
- **N3 (the bound holds in practice, not only in theory)** — arm **D**: for
  every gate, `max_top2_gap < 92.4`. Records the margin actually achieved; a
  pass at the theoretical bound with no margin is a finding, and the detail
  reports the observed maximum.
- **N4 (non-inferiority on concentration)** — arm **D**: `dead_experts_after`
  ≤ **436**, rung 4's measured value on the identical corpus, instrument and
  horizon. Equality passes: this rung claims no concentration improvement, and
  a fix that improved trainability while making routing *worse* than the
  unfixed baseline would be no fix.
- **N5 (the degeneracy is actually gone)** — arm **D**: for every gate,
  `initial_rows_with_exactly_equal_top2 == 0` and
  `initial_softmax_input_absmax <= 10.0`, and `metrics.dead_experts_before < 480`
  (the pre-training census must be a genuine routing distribution, not the
  all-rows-tie-to-expert-0 artifact).
- **N6 (control: the latch reproduces)** — arm **A**: `dead_experts_before == 480`
  **exactly** (the value two independent processes have reproduced: rung 4's
  train worker and the rung-3c re-census — this is the control for instrument
  and corpus) **and** at least one gate with `grad_zero_steps >= 1` (rung 4
  measured L31 at 40 of 48). If this fails, the control is void: the fix's
  effect cannot be attributed to the knobs rather than to a changed corpus,
  instrument, or environment, and the verdict is REFUSED for that reason —
  never an assumed pass.
- **N7 (capability guard)** — arm **D**: `candidate_holdout_loss <= base_holdout_loss × 1.10`,
  both finite. Declared as a guard against collateral damage — the fix changes
  the router's forward, and a numerics change that improved trainability while
  degrading the model beyond 10% on the frozen independent holdout is a
  regression, not a fix. This is not an improvement claim; no holdout
  improvement is required or expected at this horizon.

### 6.2 Control corroboration (INFO)

For every gate in **arm A** with `grad_zero_steps >= 1`, report whether
`any_exactly_one_hot_steps` is non-empty. If a gate's gradient dies with **zero**
exactly-one-hot rows on its own training batches, the diagnosis's mechanism
does not explain that gate's death, and the result doc must say so. No
threshold is set on this, because the quantity is ungrounded on training
batches (the diagnosis measured one-hot rows on census batches): an invented
bar here would be exactly the kind of post-hoc specification this program
forbids.

### 6.3 Declared predictions (recorded, not gating)

- **P1**: arm **C** (bounded range, artifact init) passes the N1/N2 conditions —
  the bound, not the initialization, is what prevents the latch.
- **P2**: arm **B** (initialization only) still latches: at least one gate with
  `grad_zero_steps >= 1`. Adam's per-element step is ≈ lr regardless of the
  starting magnitude, so a different starting point changes the path, not the
  existence of the saturation regime.
- **P3**: arm **B** and arm **D** show `dead_experts_before < 480` (a genuine
  pre-training distribution) while arms A and C show `== 480` (the tie-break
  artifact), on the same census corpus and instrument.

If **P2** is refuted — initialization alone prevents the latch — then the
diagnosis's mechanism ranking is wrong on that link and the diagnosis is
amended. **The thresholds are not.** A refuted prediction is a finding; a
loosened threshold is a defect.

## 7. Interpretation rules and verdict logic

- **QUALIFIED** iff every gating threshold is PASS: T1–T8 on all four arms,
  T4a as scoped, N1–N5 and N7 on arm D, N6 on arm A.
- **REFUSED** if any gating threshold FAILs, including N6 — a void control
  refuses certification rather than certifying a comparison it cannot support.
- **NOT CERTIFIED** if any gating threshold is UNKNOWN (an artifact missing or
  unreadable). UNKNOWN never becomes PASS.
- **UNKNOWN is never converted into PASS**, and a missing instrument field is
  UNKNOWN on N1–N3, not a pass by absence.
- **All attempts are preserved.** A budget-refused or preflight-refused arm is
  evidence and is reported; the arm is re-run only as an explicitly named
  attempt under its own run directory, never by reusing one.
- **Negative results stand.** If N1/N2 fail with the instrument intact and the
  control (N6) passing, the fix is refuted at this scale and that is recorded
  as the rung's result. If the run executes correctly and the science is
  negative, the result doc says so and the engineering is not blamed.
- **No threshold is changed after seeing any result**, including the envelope,
  the sub-budgets and the bars in §6.

  SQLite read-only URI, and hashes the corpora without writing. It never
  mutates the campaign root.
- **Exit code**: 0 only when every gating threshold on every arm is PASS; 1 for
  any FAIL or UNKNOWN; 2 for usage errors or a missing campaign root.
- **Verbatim capture**: the first judge run's full output is written to
  `judge-verbatim.txt` in the campaign root and quoted in the result doc
  (`P11_RUNG5_RESULT_<date>.md`) before any human interpretation. If the judge
  proves to have an instrumentation or code-location defect, the original
  refusal is preserved, the defect is proved and covered by a regression test,
  the judge is fixed narrowly, and judgment is re-run on the same immutable
  evidence. Scientific thresholds are never modified.
- **Dry-run requirement**: before the run, the judge is dry-run against rung 4's
  artifacts. It must refuse rung 4 for the reasons this prereg changes the
  contract — N1/N2/N3 unavailable-or-failing because rung 4's evidence carries
  the binary contract and not the instrument — which validates discrimination
  rather than green-ness.

  is `judge-dryrun-against-rung4-verbatim.txt` in the campaign root, produced

## 9. What qualifies at the end, stated in advance

A QUALIFIED rung 5 licenses exactly one sentence:

> On the HotCore artifact, with the logit rescale and bound at the declared
> values and non-degenerate gate initialization, the router is trainable at
> every layer: no gate latches, and every gate receives a gradient large enough
> to move its parameter on every training step, as measured by the saturation
> instrument rather than by a zero/nonzero flag.

It does **not** license: that routing concentration improved (N4 is
non-inferiority only), that the model's capability improved (N7 is a guard
only), that a longer horizon now helps, or that HotCore is a useful model. The
next rung's horizon question becomes *answerable* for the first time — because
the ladder's router capacity will no longer be spending the horizon unable to
move — and that is the whole point of doing the numerics first.
