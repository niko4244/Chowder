## Verdict

**Rung 3: REFUSED per the preregistered verdict logic — and that is a
measured, honest refusal, not a failure.** Strategy C (the only arithmetic
fit) cannot run a forward pass on stock transformers 5.16.1: every registered
experts implementation (`eager`, `batched_mm`, `grouped_mm`) calls
`F.linear(cuda_activations, cpu_weight)`, which raises
`RuntimeError: Expected all tensors to be on the same device` when expert
weights are CPU-resident. The grouped-mm kernel auto-selected on this
torch/CUDA combo additionally requires expert weights co-located with
activations. **No code path was loosened to make the artifact fit.**

A clearly-labeled **post-prereg diagnostic (D)** — not part of the preregistered
verdict — measured the amendment candidate and it **fits**: 11.368 GB peak,
1.997 s/step, all 32 gate gradients finite and non-zero (max_abs up to 0.348,
sum_abs 12.7–148.0 per sampled layer), finite loss 3.036. Details below.

### Probe defects found and fixed en route (all preserved in attempt logs)

1. Expert-tensor names from the checkpoint use a different prefix than loaded
   parameters — census re-keyed to the stable `.mlp.experts.` infix.
2. A defective strategy-C draft materialized a full CPU model to enumerate
   names (RAM grind, process death) — replaced with meta-device discovery.
3. `GATE_NAMES` global referenced after its removal — NameError.
4. Composite config: `hidden_act` lives on `text_config`, not the top level.
5. The grad check ran **after** `opt.zero_grad(set_to_none=True)`, reporting
   32/32 `none` — the attempt-5/6 "failure" was this artifact, not physics.
   Gradients are now captured on a dedicated backward before any zeroing.

Every defect is visible in `probe-stdout.attempt*.log`; none affected the
preregistered A/B/C verdicts (A/B measured before the defects mattered; C's
refusal is the library contract, reproduced identically across attempts 4).

   declaring the worker's rung-3 load policy as *bf16 + CPU-resident experts +
